## MVP 五个任务

| 任务 | 机器人怎么做 |
| --- | --- |
| 看看冰箱里还有什么 | 走到冰箱，依次开冷冻室、冷藏室，拍照，关门（冷冻室抽屉要站远一点才拉得开，两处各有站位）；照片和台账对不上会提醒 |
| 把冷冻牛肉转到冷藏层解冻 | 开冷冻室取盒，关门，开冷藏室放进空槽位，关门 |
| 把鸡米花放进空气炸锅并启动 | 取密封罐，拉出炸篮倒入，推回，罐子放回冷冻室，空着手再用接口启动（默认 12 分钟 180 度） |
| 把洗好的碗从洗碗机收到柜子 | 拉开洗碗机抽屉取碗，关上，走到碗柜开门放回原位，关门；逐个来回 |
| 把桌上散落的常用物品收回原位 | 先给桌面拍照，再把登记了原位的东西逐个送回去；没登记原位的留在桌上并提醒 |

`robohome mvp` 每个任务都从一份干净的样例厨房开始跑，做完后检查家里的状态对不对（例如鸡米花确实在炸锅里、炸锅在运行、罐子回到了冷冻室），不只看有没有报错。加 `--repeat 20` 可以按方案文档的验收标准连跑 20 次看成功率。

没有写原位（`home`）的容器，建家时放在哪个存放区，原位就是哪里。

食物可以在台账里写上做法（`cook`），相当于包装上的加热说明，例如鸡米花 `{"air_fry": {"minutes": 12, "temp_c": 180}}`。规划器照着用，主人在话里另说时间温度时以主人的为准；校验时会检查有没有家电能做、是否超出家电上限。

规则规划器只认识这五个任务的固定说法，用来在没有大模型时跑通全链路。"把牛肉拿出来解冻"这种不提冷藏的说法，规则规划器会用微波炉；大模型规划器则按常识默认转到冷藏室解冻。

运行示例：

```
任务：把牛肉拿出来解冻
  ✓ 1. navigate(waypoint="freezer_front")  —  到达 freezer_front
  ✓ 2. open(fixture="freezer_door")  —  打开冷冻室门
  ✓ 3. pick(container="box_f1")  —  从 freezer 取出冷冻盒 1 号
  ✓ 4. close(fixture="freezer_door")  —  关上冷冻室门
  ✓ 5. navigate(waypoint="counter_front")  —  到达 counter_front
  ✓ 6. open(fixture="microwave_door")  —  打开微波炉门
  ✓ 7. place(container="box_f1", location="microwave", slot=0)  —  把冷冻盒 1 号放进 microwave 槽位 0
  ✓ 8. close(fixture="microwave_door")  —  关上微波炉门
  ✓ 9. appliance(appliance="microwave", action="defrost", params={"minutes": 8})  —  调用微波炉 defrost {'minutes': 8} → running=True
完成：共 9 步
```

## 入库闭环

主人把买回来的东西摆在**入库台**上（规范文件里 `kind` 为 `intake` 的存放区，上面的包装是 `kind` 为 `parcel`、带 `label` 的容器），说一句"今天买了一斤五花肉、两盒酸奶和一袋苹果"或者"入库"，机器人：

1. 走到入库台拍一张照，读每件包装的标签
2. 识别每件是什么、放哪个温区、大概多大（关键词表，或大模型）；类别对齐台账（"饺子"按台账里的速冻饺子算"速冻"，"速冻食品"算"速冻"）
3. 按[入库怎么分配容器](#入库怎么分配容器)的规则挑容器，后面的东西能看到前面的占掉了多少地方
4. 逐件：拿起包装 → 走到容器跟前、开门 → 装进去（`stow`）→ 离开时关门。装好那一刻才记账：包装没了，容器里多了一件东西
5. 认不出、放不下的留在入库台上，用 `notify` 告诉主人原因和该做什么（"请主人拆开分装""请主人清理或添置容器"）

```
任务：今天买了一斤五花肉、两盒酸奶、一袋苹果和两箱牛奶
  ✓ 1. navigate(waypoint="intake_front")
  ✓ 2. inspect(location="intake_counter")  —  拍照：入库台：包装 1 号「一斤五花肉」、包装 2 号「两盒酸奶」……
  ✓ 3. notify(...)  —  提醒主人：包装 4 号「两箱牛奶」有 12 升，一个容器装不下，机器人不拆包装，先留在入库台上，请主人拆开分装
  ✓ 4. pick(container="parcel_1")
  ✓ 5. navigate(waypoint="freezer_front")
  ✓ 6. open(fixture="freezer_door")
  ✓ 7. stow(parcel="parcel_1", container="box_f1", name="猪肉", ...)  —  扫描包装 1 号「一斤五花肉」：猪肉，装进冷冻盒 1 号
  ✓ 8. close(fixture="freezer_door")
  ……
```

大模型只负责"认"：标签上是什么、该冷冻还是冷藏。挑容器、走动、开关门都按固定规矩写，`stow` 和 `notify` 这两个技能不出现在给大模型的技能清单里。规则规划器和大模型规划器碰到"入库""买了""超市回来"这类说法都会交给入库规划器（`planner/intake.py`）；"把昨天买的牛肉拿出来解冻"这种只是提到买、要做的是别的事的，照常按原来的任务做。

给大模型的提示词里有一张存放温区表（生肉水产速冻冷冻，乳制品鸡蛋蔬菜水果冷藏，干货调料常温），主人另有说法时听主人的。这张表是 Mac 上用 qwen3:8b 实测后加的：没有它时，小模型会把挂面放进冷冻、把西兰花放在常温。

装盒前安全规则再兜一次底：温区不对（冷冻的不进冷藏室）、要和别的类别混放，都拦下。机器人不拆包装：一件东西一个容器装不下，就留给主人拆开分装。

`robohome mvp` 里有三个入库任务，验收时每件包装都要进能放它的温区（苹果、鸡蛋、牛奶冷藏或常温都算对），登记的名字以后按包装上的叫法找得到：

| 任务 | 故障 |
| --- | --- |
| 今天买了一斤五花肉、两盒酸奶和一袋苹果 | 标签看不清（提醒）、半路掉了、冷冻室门卡住、去入库台的路被挡住 |
| 买了虾仁、一盒鸡蛋、挂面和一袋饺子 | 标签看不清（提醒）、冷冻室门卡住、包装不见了 |
| 刚从超市回来，买了鸡翅、牛奶、西兰花、酸奶和面粉 | 标签看不清（提醒）、半路掉了、冷藏室门卡住 |

Mac 上本地 qwen3:8b 验收：三句话各连跑 20 次全部通过，单次最慢约 51 秒。

`robohome intake "..." --run` 在样例厨房里先把这句话里的每样东西摆上入库台，再让机器人做；自己的规范文件里入库台上已经有包装时，直接按台上的做。加 `--sim --record out/` 在仿真里做并录成 GIF；加 `--save my_home.json --yes` 把做完后的台账写回去（留在台上的包装也记着，下次说"入库"接着处理）。

## 故障注入与停下之后

`robohome mvp --faults` 给每个任务注入几种故障（八个任务共 31 种），检查机器人是否安全停下：停在出错那一步、拍了现场照、没有启动危险家电、留下的问题都列给了主人。`missing`、`drop`、`stuck`、`blocked`、`covered` 这类规划时看不见的故障，必须是在执行时发现的才算通过；规划阶段就失败了，说明计划本身有问题，不算验证过。加 `--show-plans` 能看到大模型每一轮给的计划。

| 故障 | 含义 | 仿真里怎么体现 |
| --- | --- | --- |
| `offline:<家电>` | 家电离线，接口调不通 | 家电接口层的故障，和模拟实现一样 |
| `busy:<家电>` | 家电还在运行，例如洗碗机没洗完 | 同上 |
| `missing:<容器>` | 台账里有，实际找不到 | 场景里不放这个容器，机器人到了槽位发现是空的 |
| `drop:<容器>` | 搬运途中从手里滑落 | 走到半路松手，容器掉在地上；台账记成"地上" |
| `stuck:<部件>` | 门或抽屉卡住，开不了也关不上 | 门轴摩擦力调到拉不动，机器人用力拉也只开了一点 |
| `unknown:<存放区>` | 那里有台账里没有的东西 | 放一个台账里没有的袋子，拍照时看到 |
| `unreadable:<包装>` | 入库台上这件包装的标签看不清 | 和模拟实现一样，标签读不出来 |
| `blocked:<点位>` | 去这个点位的路被地上的东西挡住了（纸箱、没收的快递） | 点位正后方摆一个规范里没有的纸箱；机器人边走边用激光看到它，绕不过去就停下，退回出发的点位 |
| `covered:<容器>` | 容器身上的标签被挡住了（盖了块布、贴了张便条） | 标签前面盖一块布，手上的相机真的看不到标签，就不伸手 |

每一步执行前依次过三道关：**安全规则 → 技能前置条件 → 执行**，任何一关失败立刻停下并回报，不猜、不重试。

停下之后：

1. 先在原地拍一张**现场照**，随回报发给主人
2. 做一次**安全收尾**：把机器人自己打开、还没关上的门关好（收尾动作同样过安全规则和前置条件）；手里还拿着东西时只关眼前的门，不带着东西走动
3. 关不上的门、手里的东西、掉在地上的东西、倒进家电却没启动的食物，在回报里单独列为"需要人处理"

## 大模型规划器怎么工作

1. 把技能清单（带参数 Schema）和当前世界状态交给大模型，用结构化输出约束它只能返回合法的技能调用；做不到时它会说明原因。第一次说做不到时，会要求它对照世界状态核实理由，核实后还说做不到才放弃
2. **自动补全**：模型只需要写实质动作（取、放、倒、拍照、启动家电），走动和开关门由 `planner/builder.py` 按固定规矩补上：离开前关门、后面用不到的门当场就关（冷冻门和冷藏门不会一起开着）、只放空槽位、启动危险家电前先关好它的门并把手里的东西放回原处、从餐桌取东西前先拍照。家已经封装好，这些不需要大模型去想
3. 补全后的计划先在世界副本上**预演**，安全规则和前置条件都会检查
4. 预演失败就把补全后的计划和失败原因告诉大模型重新规划（默认最多 3 次）
5. 通过后交给调度器真正执行，执行时照样逐步检查，现实和台账不一致时失败即停

自动补全是在 Mac 上用 qwen3:8b 实测后加的：之前小模型经常漏关门、走错点位，每轮修一个错又冒出一个新错，3 次重试用完也规划不出空气炸锅任务。

大模型只负责"想"，不直接动手。

## 入库怎么分配容器

温区必须对上；已经装着同类、还放得下的容器优先，尽量装满一个再开下一个；一个容器只装一个类别；一个容器装不下（比如一箱牛奶）就分装到几个同温区的容器里；还是放不下就如实报告，不硬塞。

两种识别器：

- **关键词识别（默认）**：只用来演示和测试。只认一张小词表，能读"两盒""一箱""3斤"这类数量；"糖醋里脊""玉米""牛奶糖"这类关键词表判断不了的说法一律交给主人确认，宁可不认也不乱放
- **大模型识别**：能处理任意说法和照片。模型给出的每件物品都会再检查一遍（温区、体积是否合理），不合格的不入账，列给主人确认

入库默认只预览，台账不动。确认分配结果没问题后，加 `--save` 和 `--yes` 才写进台账；仓库自带的样例文件不会被改写（除非加 `--force`），先复制一份自己的：

```bash
cp data/kitchen_example.json my_home.json
robohome intake "买了一箱牛奶" --spec my_home.json --save my_home.json --yes
```

识别照片要用能看图的模型（如 `qwen2.5vl:7b`），用纯文字模型时会先提示换模型，不会白跑一趟。

## 本地模型与 Claude

任何兼容 OpenAI Chat Completions 接口的本地服务都能用（Ollama、llama.cpp server、vLLM、LM Studio），用 `--base-url` 指过去即可；也可以设环境变量 `ROBOHOME_LLM_BASE_URL`、`ROBOHOME_LLM_MODEL`。

```bash
robohome run "..." --planner local --model qwen3:14b --base-url http://192.168.1.10:11434/v1
```

本地模型用流式返回：第一个字之前最多等 3 分钟（冷启动要先把模型读进内存），开始出字后 60 秒没有新输出就判定卡住；卡住或连接中途断开会自动重试一次，整次请求超过 5 分钟直接报错。

会思考的模型（qwen3）思考时反复念同一段话、或者想了 12000 字还没给答案，就断开，不白等（Mac 上实测过 qwen3:8b 为"苹果归哪个类别"打转 5 分钟）。温度是 0 时原样再问只会再转一遍，所以打转后升温到 0.6 再试一次换条思路，还转才报错。

用 Claude 规划和识别（需要 `pip install -e ".[claude]"` 和 `ANTHROPIC_API_KEY`）：

```bash
robohome run "牛肉化一下，晚上要用" --planner claude
robohome intake "刚从超市回来，买了排骨、虾仁和一箱牛奶" --recognizer claude
robohome intake --recognizer claude --image receipt.jpg
```

## 物理仿真

```bash
pip install -e ".[sim]"                 # MuJoCo + Pillow
robohome sim-check                      # 检查规范文件的三维数据：容器放得进槽位、把手和槽位手够得着、每个点位站得下走得到
robohome sim-check --image kitchen.png  # 顺便渲染一张厨房全景图
robohome mvp --sim                      # 八个任务在仿真里跑，做完检查家里的状态
robohome mvp --sim --faults             # 故障交给物理去体现，检查机器人是否安全停下
robohome mvp --sim --record out/        # 每次执行录成 GIF，拍的照片存成 PNG
robohome run "把冷冻牛肉转到冷藏层解冻" --record out/ --fault stuck:chiller_door
robohome mvp --sim --planner local      # 本地模型规划 + 物理仿真执行
```

仿真场景完全从规范文件生成，不需要另外建模：存放区和家电写上三维尺寸（`geometry`：位置、长宽高、朝向、槽位怎么排），就能搭出柜体、隔板、抽屉、带门轴的门和容器。门轴默认放在离把手远的一边，也可以用 `hinge` 指定（`left`、`right`，往下翻的写 `bottom`）。

### 按宇树 G1 检查够不够得着

手能伸多远按宇树 G1 的公开模型算（MuJoCo Menagerie 里的 `unitree_g1`，由宇树公开的 29 自由度模型整理），脚本在 `scripts/g1_reach.py`：两脚踩平不动，可以蹲、弯腰、转腰、伸右手，手里拿 1 公斤东西也站得住（重心落在两只脚围成的范围里），只看身体正前方左右 60 度。每个高度求出手离两脚中点最远多远，再减 5 厘米余量：

| 手的高度 | 0.05 米 | 0.25 米 | 0.55 米 | 0.85 米 | 1.05 米 | 1.25 米 | 1.45 米 | 1.55 米 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 最远伸到 | 0.51 米 | 0.64 米 | 0.70 米 | 0.74 米 | 0.72 米 | 0.64 米 | 0.47 米 | 0.28 米 |

1.55 米以上够不着。这和之前估的"水平 1.1 米、高 0.05 到 1.95 米"差得多：按 G1 检查，原来的样例厨房 10 个存放区和家电里有 7 个有够不着的槽位（吊柜、碗柜太高，其余是站得太远），3 个把手也够不着，所以重新摆过：

- 吊柜（离地 1.45 米以上）换成落地的橱柜，常用的东西都放在 1.5 米以下
- 前开门的洗碗机门放平后伸出去 0.6 米，人站在门外够不到里面的碗，换成抽屉式
- 冷冻室抽屉拉出来要占地方，冷冻室和冷藏室各有站位（`freezer_front`、`fridge_front`）
- 机器人站定时脚尖离柜子大约 15 厘米，点位都按这个往前挪了

换别的机型时，按同样的方法算一张表填进 `sim/layout.py` 的 `Reach`，`robohome sim-check` 就会按它检查。

### 地上怎么走

`sim/floor.py` 只用规范数据画一张地面地图（格子边长 5 厘米）：每个存放区和家电占的地方（含柜壁和关着的门板）、柜子背后的墙和小家电下面的台面、禁区点位周围一圈（30 厘米），机器人按 G1 的身材算：走路、转身时占一个半径 25 厘米的圆，站定干活时占一个长方形（脚尖到中心 15 厘米、两边各 23 厘米）。

- 走路：在地图上找一条圆碰不到东西的路，再把折线拉直；进出点位都沿点位的朝向直着走（点位离柜子近，转不开身），退到能转身的地方再转
- 建家时检查（`robohome sim-check`）：每个点位站得下；在这个点位拉开的抽屉、打开的门不会撞到站在这里的机器人；从入口走得到每个点位
- 仿真里边走边用激光扫：身上两圈水平激光（贴地一圈、膝盖高一圈），每走 20 厘米扫一次。打到的点离规范里的家具都远，就是地上多出来的东西，加进地图；挡住了接下来的路就重新找路绕过去，绕不过去就停下，沿走过来的路退回出发的点位（台账里机器人还在那儿），再报告"路被挡住了"

### 看标签定位

容器不再"台账说在哪就在哪"：仿真里每个容器离槽位中心随机偏几厘米、转几度（像人随手放的，但不出自己的格子）。取东西时机器人不读仿真里的真实位置，而是：

1. 手先停到槽位跟前（柜子是正前方，抽屉和台面是正上方）
2. 手上的相机看容器身上的标签。每个容器正面和顶上各贴一个（类似 AprilTag 的方块码；碗和杯子贴在里面的底上，从上面看得到）。看得到要同时满足：离相机 0.8 米以内、标签大致朝着相机（差不到 60 度）、视线没被别的东西挡住（抽屉里后排盒子的正面被前排挡住，就看盖子上的）
3. 按标签算出的位置（误差几毫米）去吸；磁吸板和容器顶面中心偏差超过 1.5 厘米就吸不住，如实报告"没对准"

标签一个都看不到就不伸手，停下告诉主人。槽位里有没有东西看得出来（深度相机），是哪个容器要靠标签；买回来的包装还没贴标签，相机直接认包装本身。

技能在仿真里真的做一遍，再更新台账：

- **开门、拉抽屉**：手抓住把手，用有限的力去拉，门真的转开、抽屉真的滑出来，抽屉里的盒子跟着出来
- **取、放**：看标签认出槽位里实际是哪个容器、在哪，不是台账说的东西；放下后看它最后落在哪里，台账记实际位置
- **拍照**：看仿真里实际放着什么（包括台账里没有的东西），和台账对比，同时存一张机器人视角的照片
- **倒入、启动家电**：炸篮里出现食物，家电指示灯变红
- **装盒**：看标签找到容器，拿着包装对准它顶上松手，看它是不是真的落在容器上；落偏了、容器不在那里，都如实报告，台账不记
- **走路**：按地面地图找路、边走边用激光看，绕开地上多出来的东西

故障不再由模拟实现"按设定报错"，而是放进物理世界里让它自然发生（见上面故障表的最后一列）。`mvp --sim --faults` 里，看不见的故障（`missing`、`drop`、`stuck`、`blocked`、`covered`）必须是仿真执行时发现的才算通过。容器有偏差时，八个任务和 31 个故障在仿真里都通过。

### 简化和假设

之后换真机时要替换的部分：

- 机器人是"运动学"的：底盘和手按轨迹移动，不算关节力矩，不做全身平衡和灵巧手；够得着范围是按 G1 模型静态算的（两脚不动、慢慢伸手），走路时身体不和家具做碰撞计算，靠地面地图避开
- 开门时门板扫过的地方不检查（只检查门开到底时会不会撞到站着的机器人）
- 拍照清点还是按仿真里的真实位置判断东西在不在，看标签只用在取和装盒上
- 激光只扫水平的两圈：比贴地那圈还矮的东西、悬在半空的东西看不到
- 抓取用"磁吸"：手到位后容器直接跟着手走，不模拟夹爪
- 装盒时开盖、把东西放进去、合盖先简化成"包装落在容器上就算装进去"，装好后包装从场景里收走（末端执行器还没定）
- 家电内部（加热、计时）还是模拟家电，仿真只体现门、炸篮和指示灯
- 没有显示器的 Linux 上渲染要装 OSMesa（`apt install libosmesa6`），程序会自动设置 `MUJOCO_GL=osmesa`；渲染不可用时只跑物理，不出图。Mac 上直接能用
- Isaac Sim 需要 NVIDIA 显卡，这一阶段先用 MuJoCo；仿真层只通过 `World.body` 接到技能库，换别的仿真器只需要重写 `sim/` 这一层

## 手机入口和家庭服务器

```bash
robohome serve                                   # 在家里的电脑上开服务，打印手机要打开的地址（带配对码）
robohome serve --sim                             # 在 MuJoCo 仿真里做，回报带机器人拍的照片
robohome serve --sim --video                     # 每个任务再录一段 GIF（慢一些）
robohome serve --planner local                   # 本地模型规划，入库认标签也用它（--recognizer 可以单独换）
robohome serve --data-dir ~/robohome-home --port 8765 --spec my_home.json
```

服务只用 Python 标准库（`http.server`），默认安装就能跑。手机上是一个网页，不用装 App：

- **下指令**：说一句话，或者点一个例子。任务排队，一次只做一件，前一件做完或停下才做下一件
- **看进度**：每一步做到哪，用人话写（"走到冷冻室门前""打开冷冻室门"），不是技能调用
- **看回报**：做完或停下的原因、机器人拍的照片（`--sim` 时是仿真里头部相机拍的；不开仿真时只有文字）、提醒、需要人处理的事。点照片看大图
- **家里有什么**：每个存放区里每个容器装着什么，家电开着没有
- **再做一次、取消**：停下了、中断了的任务可以再做一次；排队中、等回答的可以取消

### 要主人拿主意的事

机器人遇到下面三种情况就停下来，在手机上问主人。等回答的时候后面的任务也先等着，免得机器人在主人还没拿主意时把家里的状态改了：

| 情况 | 手机上看到的 | 主人怎么答 |
| --- | --- | --- |
| 入库 | 入库台上每件东西认成了什么、打算放进哪个容器；认不出的、放不下的单独标出来 | 点"开始装"才动手；认不出的可以直接写它是什么，机器人按主人的说法再认一遍、重新分配，再给主人看一次 |
| 听不懂或做不了的指令 | 为什么做不了（规划器的原因原文） | 换个说法，或者算了 |
| 要停主人开着的家电 | 哪台家电正开着、不是机器人开的，停掉它才能接着做 | 点"停掉，接着做"，机器人才调用家电的停止接口，然后从头规划这件事；点"不用"就不做 |

第三种在动手之前就问：每个计划先在世界副本上预演一遍，预演发现要碰主人开着的家电，就不走过去白跑一趟。主人点了"停掉"，机器人用主人这句话当指令去停，安全规则照常检查。

入库时主人确认的是哪样就装哪样：确认后不再让识别器（尤其是大模型）重新认一遍，按确认时的识别结果和当时的台账分配。入库台上的东西在确认前后变了，就重新给主人看。

网页上"家电"那一栏有"模拟：我打开了 / 我关掉了"按钮，代替主人在家电上按开关，用来试第三种情况。真家电接进来以后，开关状态由家电自己上报。

### 存盘和重启

数据目录（默认 `~/.robohome`）里：

| 文件 | 存什么 |
| --- | --- |
| `home.json` | 台账：家里每样东西在哪，格式和规范文件一样（机器人做事做到一半时，可能记着"在机器人手里"） |
| `state.json` | 机器人在哪个点位、手里拿着什么、自己开了哪些门和家电，家电状态 |
| `tasks.json` | 任务、每一步的进度、回报、等回答的问题 |
| `photos/` | 机器人拍的照片 |
| `key` | 配对码，删掉重启就换一个 |

每做完一步存一次，写文件先写临时文件再改名，断电也不会写坏一半。第一次启动用 `--spec` 指定的规范文件建台账，之后以数据目录里的为准。重启之后：

- 排队中的任务接着排，等回答的问题接着等，回答了照常往下做
- 正在做的任务算"中断"：和失败一样拍现场照、关上机器人自己开着的门，手里拿着的东西列为需要人处理；主人可以点"再做一次"

### 只在家里的网络里能用

- 只接受家里局域网和本机来的连接（`192.168.*`、`10.*`、`172.16–31.*`、本机，以及 IPv6 的局域网地址），外网地址一律拒绝
- 每个接口都要配对码（8 位字母和数字，启动时打印；地址里带着，手机打开一次就记住了，地址栏里随后会去掉）。同一个地址 10 分钟内错 20 次就先不理它
- 走的是普通 HTTP，同一个 Wi-Fi 里的人理论上能看到内容；还没有账号和加密。外网访问以后再议
- Mac 开着防火墙的话，第一次启动会问"是否允许 Python 接受传入连接"，要点允许，手机才连得上

接口（网页就用这些，也可以自己写脚本调）：

```
GET  /api/state                 机器人状态、家里有什么、任务列表、等回答的问题
POST /api/tasks                 {"instruction": "把冷冻牛肉转到冷藏层解冻"}
POST /api/tasks/<id>/cancel     取消排队中或等回答的任务
POST /api/tasks/<id>/retry      再做一次
POST /api/questions/<id>        {"choice": "go", "fields": {"parcel_2": "牛肉"}}
POST /api/appliances/<id>       {"running": true}，模拟主人自己按家电开关
GET  /photos/<文件名>?key=…      照片
```

配对码放在请求头 `X-Robohome-Key` 里，或者网址里的 `?key=`。

## 安全原则

- 机器人不进禁区（例如灶台前）
- 机器人不直接接触热源和刀具：家电运行时不开它的门、不从里面取放东西
- 离开一个点位前，机器人在这里打开的门要先关上；任务结束时机器人打开过的门必须都关好
- 放进加热家电的容器必须标明能进这种家电（规范文件里的 `safe_for`，例如 `["microwave"]`）；食物要进空气炸锅时是倒进炸篮，不把容器放进去
- 手里拿着东西时不启动带危险的家电
- 启动带危险的家电必须给出运行分钟数，范围 1 到家电的 `max_minutes`（在规范文件里配置，默认 30）
- 读不到家电状态时按"可能正在运行"处理，不去接触它
- 不打断不是机器人自己启动、正在运行的家电（例如洗碗机没洗完、空气炸锅正在炸）：不停它，也不给它下新程序；主人在指令里明确说要停的、在手机上点了"停掉"的除外
- 入库时食物只进对的温区，一个容器只装一类东西（生肉不和饺子混放）；机器人不拆包装

机器人只负责"开启和传递"，加热、切割等工作由家电自己完成，就像调用一个封装好的函数。
